# 云海问道：AI 地形 GLB 制作工作流

生效日期：2026-10-10。用户授权：AI 执行概念图生成、Meshy Image to 3D、资产优化、地形拼接和验证；用户只审批地图与地形概念图。建筑继续由 Three.js 建模。

## 执行边界与当前状态

- 地形可见主体采用 GPT 概念图 → Meshy Image to 3D → GLB 路线。Three.js 加载、渲染、交互；建筑继续使用现有程序建模体系，动态水、云与天气继续由实时效果驱动。
- 沿用现有山海仙境的大区布局、地图范围和任务身份。不得把地图概念图视为已经完成的游戏画面；不得把图中建筑合并进 Meshy 地形。
- 可见接缝允许用脚本调整导入网格、裁切、补过渡带并导出派生 GLB。不得用新的程序化山体代替未获得的 Meshy 地形并宣称迁移完成。
- 每个独立模块验证、review 后立即本地提交，简体中文 Conventional Commit，检查 HEAD UTF-8；不 push，不混入其他工作。
- 当前仅建立流程与待审批概念图，尚未向 Meshy 提交生成任务，尚未替换游戏地形。
- Meshy API 凭据的进程与 shell 配置探测均为 MISSING；插件目录未查到 Meshy 插件。Chrome 会话读取和内置浏览器工作区访问失败，登录状态无法确认。外部执行通道尚未验证。先继续地图审批，不把外部接入问题误报为模型生成失败。

## 审批与自治规则

用户决策仅发生在以下两个节点：

1. 地图布局图：确认区域分布、主要高差、连续步行路线、建筑占地与水系。
2. 地形块概念图：按批确认山顶、山体、山脚、谷地、河床、海岸等资产的形状和统一风格。

- 生成流程不等于批准任何概念图；沉默、等待超时、AI 自评通过和“可以生成”均不是图像审批。
- 提交审批时显示实际图片，标明版本、图片路径和 SHA-256，列出该批拟建模的地形块；审批记录保存用户原话及对应版本。
- 地图通过后才生成该布局下的分块建模概念；某批地形图通过后才上传对应图片并提交 Meshy 任务。未经批准的地区继续保留原地形。
- 修改地图的区域、路线或高差，需要新的地图版本审批；改变已经批准的地形块核心轮廓或风格，需要新的地形图审批。仅修复技术缺陷、减面、压缩、局部接缝、碰撞、材质匹配不重复要求艺术审批。
- Meshy 模型、多视角检查、优化参数、网格接缝、碰撞和游戏测试由 AI 自行验收；不新增“请用户审批模型/代码/接缝”的常规节点。
- 审批后可继续当前阶段，无须用户重复说“继续”。跨对话从状态文件恢复，不能假设后台会自行持续运行；本流程不创建定时自动化或 ChatGPT Goal。
- 服务登录、凭据或额度缺失属于必要的接入障碍，单独说明。用户不需要手工上传图片、下载模型或拼地形。若必须由用户登录或在本机配置凭据，只请求这一次必要接入操作，不索取聊天中的密钥。

## 权威布局与区域拆分

权威坐标来自 `src/world/WorldLayout.ts`、`WaterLayout.ts`、`TownLayout.ts`、`SectLayout.ts`；概念图用于艺术审批，不是精确工程坐标或自动从像素推断出的地图。

- 地图：X ∈ [-500, 300]，Z ∈ [-300, 300]；北方为 -Z，1 个世界单位按 1 米解释。
- 云岚宗：中心 (0, 7)，峰顶约 90m；保持山脚 → 山门 → 峰顶的连续步行路线。已有路线/广场/建筑地基是工程约束，不要求 AI 图片准确画出每个顶点。
- 苍翠林：西侧 (-407, -123) 附近；保持林间通路与空地。
- 松风林/玉镜潭/望月台任务点身份：(-110, -70)、(105, -135)、(0, -245)；镇山试炼位于北方约 (0, -280)。望月台/镇山台任务场地保持约 2.7m 的低谷平地，周边可有高山脊。不得把任务点与实际玉镜潭池水中心混为同一个坐标。
- 叠瀑谷：东侧 (178, -146) 附近；保留上游高地、两级瀑布、玉镜潭池水 (130, -120)、下游河道至海岸的空间。
- 听潮坊：(125, 83) 附近，预留约 10.2m 宽主街与现有店铺地基。
- 听潮海岸：南侧，保留浅海/沙滩与入海河口；海岸线按现有共享函数复核。
- 远山：可玩边界以外，单独加载与 LOD，不承担任务区域行走。

先完成“宗门山顶 + 主体山体 + 山脚 + 上山路径”的可玩样区，再扩展山谷、林地、水系、城镇和海岸。各批资产清单由批准布局决定，不一次批量生成整张世界。

## 阶段与交付

| 阶段 | AI 执行 | 用户介入 | 完成证据 |
|---|---|---|---|
| A 地图规划 | 从现有坐标生成分区规划及 GPT 总览图，审查道路、水系和建筑占地 | 审批地图图像 | 图片、提示词、SHA-256、用户原话 |
| B 地形概念 | 每块生成独立、可用于建模的 GPT 输入图；给出编号、目标大小与连接区 | 按批审批地形图 | 独立图片、资产列表、审批哈希 |
| C Meshy 建模 | 上传批准输入图，提交 Image to 3D，记录任务 ID，等待并下载 GLB | 无常规审批 | 真实任务 ID、下载哈希、参数与消耗记录 |
| D 资产整理 | 检查几何/材质，减面、纹理压缩、尺度/原点校准、LOD 与碰撞低模 | 无常规审批 | 多视角截图、统计、LOD/碰撞派生文件 |
| E 拼接 | 组装区域，处理边缘/高差/河床，放置 Three.js 建筑与动态水系 | 无常规审批 | 区块变换、连接记录、实际场景截图 |
| F 可玩验收 | 步行、御剑、降落、存档恢复、任务路线、性能与图像检查 | 无常规审批 | 构建/受影响测试、真实输入视频、测量与截图 |
| G 扩区 | 复用通过的样区方法，一批地形一批推进 | 只审批新地形图或实质地图变更 | 每批独立证据和本地提交 |

## GPT 图像要求

- 使用内置 image_gen，不切换成 Gemini/Tripo；本项目指定 Meshy 作为模型来源。
- 总览审批图可以呈现建筑占地/少量建筑示意与水系，必须声明仅用于布局和美术方向，不能直接作为整个世界的 Image to 3D 输入。
- 分块建模图：单个完整地形主体占画面约 75–85%，三分之四俯视；纯净背景，无文字、坐标网格、雾、云、水面、建筑、人物、树群和装饰底座。
- 河谷模型表现干河床和岸坡，实时水面独立；山顶模型表现平台和岩壁，Three.js 建筑独立；林地地块保留路面，植被独立。
- 统一青灰岩、克制苔藓、自然风化与可辨识的轮廓；柔和均匀照明，避免强烈烘焙阴影。优先大尺度结构，细碎岩纹可用 PBR 贴图。
- 外露边界、路径入口/出口和预留平地先由 AI 审图，再送用户图像审批。图片不能保证精准坡度、平面度、尺度或接口，实际 GLB 必须测量并修整。
- 一个地形块一个输入图。审批联系表可以展示多块，但不得把带多个视角/多个主体/文字的拼图直接上传成单图建模输入。

## Meshy 接入与任务恢复

优先使用 Meshy 官方 API；若只有已登录工作区，可通过受支持的浏览器 UI 上传/提交/下载。浏览器不可访问或登录未验证时不能承诺已经全自动接通。不得绕过登录、验证码或访问控制，不把 API key 写进项目或浏览器脚本。

建议的首轮 Image to 3D 参数（经官方文档核对，2026-10-10）：

```json
{
  "ai_model": "meshy-7.1",
  "geometry_resolution": "standard",
  "model_type": "standard",
  "should_texture": true,
  "enable_pbr": true,
  "texture_resolution": "2k",
  "image_enhancement": false,
  "should_remesh": true,
  "topology": "triangle",
  "target_polycount": 100000,
  "save_pre_remeshed_model": true,
  "target_formats": ["glb"]
}
```

- 此参数是大块宗门地形的起点；普通地块先试 30000–60000 三角面，远景约 10000–20000；最终面数需以近景轮廓、纹理清晰度和整幅画面性能测量为准。
- `target_polycount` 需要启用 remesh；不同时指定会覆盖它的 adaptive `decimation_mode`。原始输出与派生输出分别保留，GLB 实测面数才是验收数据。
- API 支持图片 data URI，可直接发送批准的 PNG，不必把项目图片公开托管；UI 路线使用正常文件上传。提交前再次核对审批文件 SHA-256。
- 每次受理立即保存 provider、task_id、asset_id、批准图像哈希、请求参数、状态与检查点；不保存密钥或短期签名下载 URL。
- 正常 GET/status/download 可有限重试并遵守限流；POST 提交不得盲目重试。结果不确定先查任务历史/已有 ID，不能重复扣费提交。
- 任务成功后立即下载，下载链接过期时重新读取已有任务，不重生成资产。已有模型可在审批形状一致时复用；之前的山顶候选保留待评估。
- 默认每资产最多 1 次初始生成、1 次经诊断的模型修正生成；优化优先本地执行，确有必要再进行 1 次 Meshy Remesh。额度不足停止该服务阶段，不购买/充值/订阅/升级。超过该数量不自动进行新增付费尝试。
- 若浏览器或服务要求单独的费用/权限确认，说明具体动作、费用或权限来源；这类接入限制不伪装成艺术审批。

## 拼接工程约束

- 先把最大主体定位，再匹配山顶、山脚和道路；不能用模型包围盒平顶冒充实际可走地面。
- 非行走岩壁可有限重叠、埋边、覆盖岩石；避免共面闪烁与飞行侧视的巨大穿插。遮住裂缝不代表碰撞连续。
- 主要行走入口需要地面高度和坡度连续。接缝局部做裁切/平整/过渡带，或者使用适配的 Meshy GLB 路径模块。编辑后的可见几何导出派生 GLB，记录来源和加工步骤。
- 建筑、门、亭、广场和台阶沿用 Three.js；地基须对齐 GLB 表面，确保入口与地形不悬空/互相掩埋。
- 地形碰撞以导入模型或局部接缝派生网格生成并校验。低模必须保住道路边界、落脚高度与陡崖轮廓；不能仅继续旧 terrainHeight 导致人物浮空。
- 单层地表可预采样模型得到高度缓存；悬挑、洞穴、桥梁或上下叠层区域采用三维碰撞/空间加速，不能用从天空取最高交点当作万能行走高度。
- 导航坡度、角色步高、足底容差依据当前控制器测量后设定，不能把示意图参数当作已经通过的工程指标。
- 地图舆图、草药/敌人/宝箱/NPC摆放、天气表面、元素技能和存档恢复都要接入同一份地形查询/区域注册，防止只改视觉却保留旧地面。
- 一次只启用验证通过的区域，保留切换/回退路径。全部批准且迁移区域验证通过之后，才能删除旧的对应可见程序化地形。

## AI 自验收与提交

每个可玩区域至少检查：

1. GLB 可加载、没有必需外部文件缺失；记录大小、SHA-256、面数、网格/材质/贴图数、纹理尺寸、坐标/原点与边界。
2. 模型顶、底、四侧和近景检查，确认没有明显孔洞、悬浮碎片、阴影烘焙、材质反光或拉伸问题。
3. 连接区沿路线中心和两侧密集采样；检查可见表面/碰撞高度、台阶、高差、坡度和角色身体净空。
4. 真实输入从山脚连续走到宗门，再下山；覆盖转弯、跨区、御剑低飞/降落/贴崖、旧存档恢复与相机遮挡。
5. `npm run build`、受影响地形/宗门/水系/城镇/任务测试；图像和性能检查使用实际 GPU 浏览器，不能只拿模型预览代替实机验收。
6. 各目标视角记录 renderer calls/triangles/textures、帧率、资源加载和 LOD 切换。现有场景已包含重型角色/武器/建筑，预算看总画面而非每块孤立模型；不得声称未测量的性能改善。
7. 完成源码/差异 review 后只暂存该模块文件，创建中文本地提交并立即检查 HEAD UTF-8。提交失败保留成果并记录失败。

## 文件与状态约定

- 工作流：`docs/ai-terrain-workflow.md`
- 活跃计划：`artifacts/terrain-pipeline/plan.json`，记录地图版本、阶段、分区、图片/模型批准状态和服务接入证据。
- 地图图像与提示词：`artifacts/terrain-pipeline/concepts/map-v1/`；修改生成新的 `map-v2/`。
- 分块图像：`artifacts/terrain-pipeline/concepts/<batch-id>/<asset-id>/`；原始模型/任务检查点与 QA 保存至同批目录。
- 游戏资产：`public/assets/terrain/<region-id>/`，仅放经验证的运行时 GLB/纹理/碰撞数据。
- 制作进度：`artifacts/game-progress.md`，记录已完成模块、验证结果、提交标识、当前审批与服务任务；每次继续先读本节及活跃计划。

阶段状态：`planning` → `awaiting_map_approval` → `creating_asset_concepts` → `awaiting_asset_approval` → `generating_models` → `reviewing_models` → `optimizing` → `assembling` → `validating` → `complete`。服务接入问题另记 `provider_access`，不把尚未发生的模型阶段标成完成。
