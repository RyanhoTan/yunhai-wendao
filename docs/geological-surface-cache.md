# 陆地岩面离线缓存

岩面细分属于固定地图的构建步骤。玩家启动时加载与当前源码匹配的索引几何，不再执行整山自适应细分。此改动不修改地图、道路、建筑、任务或存档格式。

`npm run bake:geology` 生成缓存；`npm run build` 和 `npm run dev` 在开始前检查并按需生成。生成目录为 `public/assets/terrain/geological/`，属于可再生成的派生文件，不提交大型二进制。部署使用正常构建的 `dist/`，包含实际缓存资源。修改地形生成依赖后须重新运行上述命令；已有开发服务器应重启，不依靠热更新替换岩面。

缓存包含各48米批次的Float64世界点、Float32法线、Uint32三角索引、实际雨遮挡包围体与细分统计。渲染仍按原路径把世界点转成Float32；身体碰撞保留原Float64坐标，按相同顶点和三角顺序调用原SAT构造函数。镜头使用实际渲染网格。构建时对编码后再解码的全部数组作逐字节对照。

构建脚本递归记录生成器、地形场及其本地依赖，同时记录脚本自身与Three.js包版本内容。源码哈希决定二进制文件名；清单另含二进制SHA-256和长度。构建前拒绝使用失效缓存。浏览器在创建Game之前检查清单版本、构建哈希、文件名、长度、SHA-256、格式和索引范围；加载失败显示现有资源重试界面，不自动退回昂贵的实时生成。

碰撞不常驻全部SAT轴。每个批次使用4米XZ格子的压缩索引，查询时按原三角序筛选并计算附近三角的原SAT。所有格子覆盖身体扩张后的真实包围体；植物查询仍保留原身体反扩张规则。几何数组和索引构建后视为只读，变更几何须重新构造空间索引。

`bodyCollisionBytes`为碰撞所用typed-array视图的有效载荷；`bodyCollisionBackingBytes`另外披露这些视图实际保留的去重后ArrayBuffer容量，包括共享缓存缓冲中的法线和雨遮挡数据。二者都不代表浏览器总内存或GPU显存。

缓存正确性与构建成功不能证明画质达到LAAS。仍需同位置同时间截图、自由探索、道路与镜头检查、帧耗时、海岸回归和完整视觉验收。原失败记录保留，启动门禁不能通过延长等待时间来改写。
