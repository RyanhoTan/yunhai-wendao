# 实际GPU缓冲视口修复

最终视觉验收的首轮基线被独立审图拒绝：角色前后/特写跑到右侧画外，多数招式与宗门视角只剩地面，不能当作通过基线。样本和审查哈希保存在`../baselines-final/rejected-r1/`；旧accepted基线已逐字节恢复。

定位：当前有界面Chromium的窗口后端与deviceScaleFactor模拟组合下，canvas声明1280×720，但WebGL实际绘图缓冲为640×360，viewport仍1280×720。相机位置和目标正确，问题是视口超出物理缓冲，截图被裁切。未推测GPU内存压力或改变全局浏览器设置。

修复：`resizeRenderer`每帧核对实际GPU缓冲，校正renderer的逻辑viewport（除以renderer pixelRatio），让影子绘制与默认目标恢复也沿用该viewport；绘图缓冲为0时跳过。相机保持CSS比例，同尺寸时不重复设置。

验证：生产构建通过，真实窗口1280×720→1100×700→1280×720回归15.1秒通过。物理缓冲分别为640×360、1100×700、640×360，三个viewport均完整匹配，冻结角色renderPosition与权威位置相同。`character-front.png`已审查人物居中。该后端仍会把640×360采样放大到1280×720；最终画质基线使用另一受支持的X11窗口后端及实测1280×720物理缓冲，不用放宽误差阈值或遮罩。
