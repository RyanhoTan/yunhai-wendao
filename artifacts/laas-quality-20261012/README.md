## 参照来源

`reference-live/` 保存本轮自行运行 LAAS 的 NVIDIA WebGPU 画面、参数、实际适配器、日志和部署 JS 哈希。线上部署未提供提交标识，不能把它直接归属仓库的某个 commit。时刻的改变必须核对实际运行：LAAS 的 HUD 打印启动参数，书签也可能覆盖启动 `T`，所以仅凭请求参数、文件名或调用 setter 不认定黄金时段已生效。

`reference/author-runtime-*.png` 为仓库作者的历史实际运行截图，来源和原始哈希在 `author-runtime-sources.json`；它们不是本机复现，也不是 `reference/` 下的目标概念图。早先包含 golden 字样的名称不作为实际时间证明，以源元数据与核对记录为准。

## 起点十大差距与修复顺序

以下由玩家基线与 LAAS 实际输出对照得出；帧率、面数和代码量不作为画质替代证据。

1. **主山与重点岩壁**：大片连续平滑崖面和简化轮廓，缺少真正凸出的层理岩台、破碎断口与侵蚀沟槽。先处理真实地质几何。
2. **树形与冠层**：相似直干、少数重复分枝模板、薄而尖锐的叶面，缺少不同年龄和树种形成的体积冠层。随后处理分枝与叶簇结构。
3. **10 米内地表**：草簇之间大片平整地面，缺少灌木、花卉、细枝、树皮碎片、小石、腐朽倒木和根边生态。随后补齐贴地实体覆盖。
4. 远山轮廓与坡面仍像简化山块，缺少连续破碎山脊和能在远处成立的岩层方向。
5. 山肩和山谷树群稀薄，林冠高度与群簇变化不足，无法形成有起伏的树冠海洋。
6. 岩石大面材质色差偏单一，矿物层、湿度、风化、苔藓与地衣未形成与形体相符的附着关系。
7. 林冠内部以暗色叶面为主，缺少逆光透光、细枝与不同叶簇之间的受光差异。
8. 树根形状简化，根部与土壤、枯落物、菌类和林下植物的关系薄弱。
9. 缺少可辨认的幼树、枯死个体、倒木与林缘更新状态；现有分布虽避开道路水体，生态层次仍有限。
10. 实体细节的远近变化与风动尚未完成连续移动对照；源码中的硬 LOD 切换及不同叶片尺寸、仅叶片小幅摆动，需要重点检查弹出、形变与动态稳定性。这一项为源码风险和未完成验证，不声称已拍到所有运动缺陷。

前三项将在各自完整模块里修复并重新截图；此单元完成固定取景、真实参照和性能测量工具，不把未开始的环境实现描述为完成。

## 失败与 review

`before/`、`before-r1/`、`before-r2/` 是早期路径错误、驱动不匹配、软件取景或中断的诊断。`before-hardware-r1/` 全部硬件取景与输入成功，但宗门建筑被主山挡住，视觉取景被拒绝，状态已注明。所有记录保留。

`provenance-negative-r1/` 故意注入旧源映射，验证运行器在浏览器启动前拒绝旧构建并记录终止状态；生成目录随后原字节恢复。

[独立 review](review-capture.json) 包含源码哈希、具体问题、修复核对和 r2 实机证据。修复内容包括 PNG 路径、合法高度、GPU 真伪、错误采集、失败状态、预览与实际 JS 版本绑定、唯一目录、稳定落地、活动采样超时及真正可见宗门的取景。

海面、海岸、建筑、地图、任务和存档实现均未修改。旧 GLB 任务保持暂停；未调用外部模型生成服务，未 push。
